Pipeline

Why two segmentation paths?

The original production path deduplicates pages before segmentation. The independent review identified a structural risk: legitimate repeated pages can disappear before boundary inference. The second-pass audit keeps the original page stream for segmentation, then fingerprints duplicate document occurrences afterwards. The project now supports A/B validation before choosing one architecture as canonical.

Run locally

git clone https://github.com/joshualparris/pdfresearch.git
cd pdfresearch
python -m venv .venv
# activate the venv, then:
pip install -e .
pdfresearch run "_DEEP_RESEARCH_.pdf" --output "pdfresearch-output" --no-pdfs

Review targets

Boundary precision

Inspect known report starts/ends and near-threshold candidates rather than tuning to a target count.

Duplicate safety

Check boilerplate pages, scans, forms and repeated pages inside legitimate source documents.

Reference classification

Ensure reports discussing books are not misclassified as the books themselves.

Scale

Profile extraction, cache size, memory use and PDF rewriting around 25k pages.
